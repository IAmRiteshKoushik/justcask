Justcask lesson 0012 · 20 minutes

Never write what you cannot read

The decoder now rejects oversized records. The encoder must apply the same policy or Justcask can manufacture durable bytes that it refuses to reopen.

The symmetry invariant

if Encode(record) succeeds,
then Decode(encoded bytes) must be allowed to succeed.

This is stronger than “both functions have limits.” It says the writer cannot produce an artifact that violates the reader’s contract.

Two tests to add

  1. Create a record with a key of maxKeyLength + 1 bytes and a small or empty value. Expect ErrRecordTooLarge.
  2. Create a record with a value of maxValueLength + 1 bytes and a small or empty key. Expect ErrRecordTooLarge.

In both tests, assert that Encode returns no data. It must refuse before allocating the record buffer. Using a 16 MiB plus one-byte test value is acceptable here: it tests the exact policy boundary and does not write it to disk.

Expected initial failure

The current encoder will allocate a byte slice, return it, and return no error. Your tests should fail for that reason. Do not modify Encode until you have seen the failing result.

Your task

  1. Add the two encode-limit tests using errors.Is.
  2. Assert a nil byte slice on error.
  3. Run go test ./internal/record and send the failure output.
