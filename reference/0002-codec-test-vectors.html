Justcask reference 0002

Codec test vectors

Use these as examples of the kind of test you will write. Do not make the production encoder calculate the expected bytes for the test.

One deterministic put record

The record has timestamp 0x0102030405060708, key go, and value DB.

field             hex bytes
crc32/IEEE        5d 6e be 22
timestamp          01 02 03 04 05 06 07 08
key length         00 00 00 02
value length       00 00 00 02
key                67 6f
value              44 42

whole record       5d6ebe2201020304050607080000000200000002676f4442

The CRC is calculated over every byte after 5d 6e be 22. The expected bytes use big-endian integers. A decoder should return the same timestamp, key, and value from this literal vector.

Three decoder cases

  1. Known valid vector. Give the full 24-byte literal above to the decoder. Expect one decoded record with the stated timestamp, key, and value.
  2. Truncated tail. Remove the last byte, making the value one byte short. Expect an incomplete-record result. A recovery scanner may ignore this only when it is at physical EOF.
  3. Checksum mismatch. Change the final byte from 42 to 43 but leave the stored checksum unchanged. Expect a checksum-mismatch error, not a decoded record.

Return to lesson 0004. The exact record format lives in DECISIONS.md.
