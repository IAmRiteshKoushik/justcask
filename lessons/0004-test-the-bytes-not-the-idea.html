Test the bytes, not the idea

A round-trip test can pass when encoder and decoder share the same mistake. A storage format earns trust when a test asserts the exact bytes on disk.

The blind spot in round trips

Suppose your encoder accidentally writes the value length in little-endian and your decoder accidentally reads it in little-endian. decode(encode(record)) passes, but the database has violated its big-endian file contract. An exact-byte test catches it.

encode(record) -> exact, precomputed byte slice
decode(exact byte slice) -> expected record
decode(truncated byte slice) -> incomplete-record result
decode(byte slice with one flipped protected byte) -> checksum error

Pick values that expose mistakes

Do not choose all-zero numbers. They hide byte order. A good fixed vector uses a timestamp and lengths whose bytes differ, a short ASCII key, and a short ASCII value. You will calculate its expected bytes once, write them as a literal hexadecimal test vector, and never calculate the expected result by calling the production encoder.

Decoder rule. Before allocating the declared key or value buffers, reject lengths that exceed your configured maximum or cannot fit in a safe allocation. Disk bytes are input, not a promise.

Your test plan

Before writing code, reply with:

  1. The timestamp representation you choose: signed or unsigned, and its unit.
  2. A key and value for one deterministic exact-byte test. Pick a non-zero timestamp that makes endianness visible.
  3. Three decoder test cases, each with the input condition and expected outcome.

After you make these choices, you will create the codec package, test file, and only the first failing test. I will review the package boundary and test names before you implement the encoder.

Read the current format decisions. The Go references for this stage are `encoding/binary`, `hash/crc32`, and `testing`.
