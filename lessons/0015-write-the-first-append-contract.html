Write the first append contract

A data file does not know keys. It accepts opaque encoded bytes, writes them once at the end of one open file, and reports the range they now occupy.

Keep the package narrow

Create internal/datafile. Its first production responsibilities are:

  1. Open one writable data file for a supplied path and file ID.
  2. Append one supplied byte slice.
  3. Return the file ID, pre-write offset, and number of bytes written only after a full successful write.
  4. Close the underlying file.

It should not import the record package, decode bytes, update a keydir, rotate files, or call sync yet.

The first test contract

Use t.TempDir() to create an isolated file. Pick file ID 7. Append two distinct opaque byte slices, for example a three-byte first slice and a two-byte second slice.

append first bytes  → location { file ID: 7, offset: 0, size: 3 }
append second bytes → location { file ID: 7, offset: 3, size: 2 }
read file           → first bytes followed exactly by second bytes

The actual byte values do not matter. Their distinction does. A generic data-file test proves this layer appends bytes, while a later store integration test will prove it appends encoded records.

Implementation constraints to hold in mind

  • Capture the offset before the write, not after it.
  • A write that returns fewer bytes than supplied is an error. It must return no successful location.
  • The size in the location is the full byte-slice length, not a value length.
