Bitcask glossary

Append-only log
A file where a write adds a new record at the end. Updating a key does not overwrite its older record.
Record
One self-describing sequence of bytes representing a put or delete. Its format is a compatibility contract.
Keydir
An in-memory map from a live key to the location of its newest record, typically file ID, offset, and value size.
Active file
The one data file receiving appends. Older files become immutable when the active file rotates.
Tombstone
A record that means a key was deleted. It must survive until compaction can safely discard it with older versions.
Recovery
Rebuilding correct in-memory state when opening the directory by scanning valid records in physical order.
Crash tail
An incomplete or corrupt final record caused by a process or machine stopping during an append.
Compaction or merge
Rewriting only the latest live records into new files, then retiring stale files safely.
