Test every crash cut

A process can stop after any byte reaches the active file. One hand-picked truncation test proves little. A loop over every shorter prefix proves the decoder has one consistent crash-tail rule.

The property

Given one known-valid record of length 24, every prefix with a length from 0 through 23 must return ErrIncompleteRecord and a zero Record. The complete 24-byte input must still decode successfully.

valid bytes:        [ b0 b1 b2 ... b23 ]
valid crash tails:  [] [b0] [b0 b1] ... [b0 ... b22]
expected result:    ErrIncompleteRecord for every crash tail

Keep the fixture honest

Add a small test helper that returns a new copy of the literal 24-byte v1 vector. It must not call Encode. A shared fixed fixture removes repeated setup while keeping the test independent from production code.

In Go 1.27, use integer range syntax to visit every prefix length. The loop has a natural endpoint: iterate through len(valid), excluding the complete length.

What the loop must assert

  1. Slice the valid vector to the current prefix length.
  2. Call Decode.
  3. Assert errors.Is(err, ErrIncompleteRecord).
  4. Assert the returned record is zero.
  5. Include the prefix length in any failure message, so the failing crash point is immediately visible.

Why this is more than coverage. The test does not care whether a cut lands in the checksum, timestamp, length fields, key, or value. It states the storage invariant that all those physical crash points share: incomplete bytes never become a decoded record.

Your task

  1. Add the literal-vector helper and the exhaustive-prefix test.
  2. Run go test ./internal/record.
  3. Tell me how many truncated prefixes your test exercises and why the complete record is excluded from the loop.

Do not change production code for this lesson. If the test fails, its prefix length points to the boundary rule that needs attention.
