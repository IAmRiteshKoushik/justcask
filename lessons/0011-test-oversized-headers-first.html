Justcask lesson 0011 · 20 minutes

Test oversized headers first

The length fields are untrusted until decode accepts them. Test the refusal at the 20-byte header boundary, before a declared body exists.

The new category

Add ErrRecordTooLarge as a stable error in err.go. It means the header declares a key or value above Justcask’s accepted limit. It is neither a normal crash tail nor a checksum mismatch.

Two compact tests

Add one test for an oversized key and one for an oversized value. Each test uses only a 20-byte header:

  1. Allocate a byte slice exactly the fixed header length.
  2. Write a declared key or value length of one byte above its chosen limit at the correct big-endian offset.
  3. Call Decode.
  4. Assert a zero record and errors.Is(err, ErrRecordTooLarge).

Do not calculate a CRC or attach a key/value body. The intended rule is that the decoder rejects an unacceptable declaration before checking whether the body exists or whether its checksum matches.

Expected initial failure

Your current decoder will classify these headers as incomplete because their declared bodies are absent. That is the point of the test. The next implementation step will insert the size checks immediately after it reads both length fields and before it calculates the declared record size.

Your task

  1. Add ErrRecordTooLarge.
  2. Add the two header-only tests, using the 4 KiB and 16 MiB decisions.
  3. Run go test ./internal/record and send the failing output.

Once they fail for the intended reason, we will make the decoder reject them. After that, we will stop the encoder from producing records it cannot later read.
