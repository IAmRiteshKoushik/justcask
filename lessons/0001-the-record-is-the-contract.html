The record is the contract

Your CLI will recover only what it can unambiguously parse. Before writing a database API, decide what one durable operation looks like as bytes.

The one idea

Bitcask writes each new value at the end of a data file. The keydir keeps the location of the newest record for each key, so a read finds the record with one indexed disk access. Old versions remain until compaction.

[ checksum | timestamp | key length | value length | key bytes | value bytes ]

This is the original paper's shape, not a command to copy it blindly. A record needs enough information to find its boundary, identify its key, recover order, and reject damaged bytes. A delete can use the same envelope with an explicit operation field or a documented sentinel. We will choose deliberately.
