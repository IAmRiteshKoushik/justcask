Understand short writes

A short write means fewer bytes reached the file than you requested. That is not a successful append, even when some bytes did reach the operating system.

What the Go contracts already guarantee

os.File.Write returns a non-nil error when it writes fewer bytes than requested. The general io.Writer contract says the same thing. Therefore, while DataFile directly holds an *os.File, its existing err != nil check rejects every valid short write.

Do not add a second branch for n != len(data) yet. It would be unreachable for a correctly implemented *os.File.

What io.ErrShortWrite means

io.ErrShortWrite represents a broken writer that reports fewer bytes but no error. It is useful as a defensive category when consuming an unknown writer. It is not the normal result you need to manufacture around os.File.Write.

Two review fixes

  • When adding context to a real OS error from Stat or Write, wrap it so its identity remains available to callers.
  • State that the current offset calculation assumes one writer per data file. Concurrent appends arrive later with an explicit synchronization design.
