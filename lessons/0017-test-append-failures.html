Test append failures

Your happy-path append test proves where bytes go. Now prove that a failed append cannot hand the future keydir a location that looks valid.

Introduce one private file contract

DataFile calls only three methods on its underlying file: Stat, Write, and Close. Replace the private *os.File field with a private interface containing exactly those methods. Keep Open unchanged in spirit: it opens a real *os.File, which satisfies the interface.

This is dependency injection in its smallest useful form. The production path remains an OS file. The test gets a fake file whose methods return the failure you want to study.

The two tests to add

Fake behaviorRequired result
Stat returns a sentinel error.Append returns the zero Location, preserves that error for errors.Is, and does not call Write.
Stat reports an offset. Write returns len(data)-1, io.ErrShortWrite.Append returns the zero Location and preserves io.ErrShortWrite for errors.Is.

The second fake follows the io.Writer contract. It records partial progress and a non-nil error. Your existing error path should reject it without a special short-write branch.

One uncomfortable fact

A failed partial write can leave bytes at the end of the real file. Returning a zero location prevents an incorrect keydir update, but it does not erase those bytes. Do not try to solve that policy in this lesson. The next one will decide whether the active file becomes unusable after a failed write or whether the store can safely repair it.
