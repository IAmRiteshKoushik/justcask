Read one record from a stream

Put frame boundaries beside the record format. Recovery should ask the record package for one validated record, not duplicate header parsing in the data-file layer.

The recommended API

func ReadFrom(r io.Reader) (Record, int, error)

The returned integer is the number of bytes consumed for a successful record. The recovery scanner uses it to build a location and advance its offset. It does not need the header width or the key and value offsets.

Implement it in two reads

  1. Use io.ReadFull to read the fixed 20-byte header.
  2. From that header, validate the key and value lengths before allocating anything.
  3. Allocate one buffer for the full declared record. Copy the header into it.
  4. Use io.ReadFull again for the remaining key and value bytes.
  5. Pass the full buffer to the existing Decode. It remains the checksum authority.

Write these tests first

  1. An empty bytes.Reader returns io.EOF.
  2. A valid encoded record returns the original record and its exact encoded byte count.
  3. Every non-empty truncated prefix of a valid encoded record returns io.ErrUnexpectedEOF.
  4. A complete record with one flipped data byte returns ErrChecksumMismatch.

Do not build the data-file scanner yet. Make this one-record reader reliable first. It turns the restart problem into a simple offset loop.

Retrieval check

Why should ReadFrom return io.ErrUnexpectedEOF for a partial record instead of converting it to ErrIncompleteRecord? Answer before coding.
