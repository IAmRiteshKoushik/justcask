Prove that a file appends

The first data-file test has one job: prove that successive writes occupy successive physical ranges and that the returned locations tell the truth.

Location types

Use a file ID, an offset, and a size. Pick concrete Go types before implementation:

FieldRecommended typeReason
File IDuint32A non-negative segment identity with ample room for rotations.
Offsetint64Go file APIs use byte offsets as int64. Negative offsets remain invalid by invariant.
Sizeuint32One encoded record is bounded by the 4 KiB key and 16 MiB value limits.

The first append proof

Use a temporary directory and one new data file with a chosen file ID, such as 7. Append the valid 24-byte v1 fixture twice. The test should observe:

first location:   file ID 7, offset 0,  size 24
second location:  file ID 7, offset 24, size 24
file contents:    first bytes followed exactly by second bytes

Do not involve the keydir, decoding, file rotation, sync, or reopening yet. This test is a narrow statement that append returns the physical range it just occupied.

Your design decision

Reply with the three concrete field types you choose. Then answer one question: if the second append returns offset 24 but the file has only 24 bytes afterward, what invariant did the data-file layer violate?
