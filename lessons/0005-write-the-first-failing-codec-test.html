Write the first failing codec test

The codec turns an in-memory record into its durable bytes and back. It should know nothing about files, keydirs, or the CLI.

Package boundary

Create internal/record. The name is intentional: this package owns the on-disk record format. A later storage package will open files and call it; the CLI will not import it directly.

internal/record/
  record.go       // Record type and Encode/Decode
  record_test.go  // exact byte vectors and invalid inputs

Start with only this model and these operations:

type Record struct {
    Timestamp int64
    Key       []byte
    Value     []byte
}

func Encode(record Record) ([]byte, error)
func Decode(data []byte) (Record, error)

Do not add file I/O, options, concurrency, a database handle, or delete support. Those would obscure the format work.

First test, before implementation

In record_test.go, write one test named TestEncodeProducesV1Bytes. Construct the record from the worked vector and compare Encode's result against a literal 24-byte expected slice.

Make failure output useful. On a mismatch, print both byte sequences in hexadecimal. Avoid constructing the expected sequence with Encode, binary.BigEndian, or crc32; that would repeat the production logic inside the assertion.

Prediction. Your first test should not compile until you define the package API. After it compiles, it should fail because Encode has not written the record yet. Both failures are progress: each names the next smallest piece of work.
