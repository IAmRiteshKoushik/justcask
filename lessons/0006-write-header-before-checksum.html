Write the header before the checksum

The first four bytes are the checksum, but they should be the last bytes you fill. Everything it protects has to exist first.

Offset map

offset  0..3   checksum, u32 big-endian
offset  4..11  timestamp, int64 encoded as its u64 bit pattern
offset 12..15  key length, u32 big-endian
offset 16..19  value length, u32 big-endian
offset 20..    key bytes, then value bytes

The total allocation is 20 + len(key) + len(value). Convert the signed timestamp to uint64 only for serialization. That preserves its two's-complement bit pattern, including timestamps before the Unix epoch.

Implementation sequence

  1. Replace the TODO in Encode with a single byte slice of the exact total size.
  2. Use binary.BigEndian.PutUint64 and PutUint32 to fill offsets 4 through 19.
  3. Copy the key to offset 20, then copy the value immediately after the key.
  4. Calculate crc32.ChecksumIEEE over encoded[4:].
  5. Write that checksum into encoded[0:4] with PutUint32, then return the bytes.

For this first pass, return a nil error for the small test record. We will add explicit key/value size limits and error tests directly after the happy path works.

Stop and predict. If you calculate the CRC over the full slice before writing its checksum field, it happens to work only because a newly allocated Go slice is zeroed. The format's real rule is stronger: checksum every byte after offset 3. Encode that rule in the slice range.
