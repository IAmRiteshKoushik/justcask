Make decode prove itself

Decode must trust the bytes on disk, not the encoder that happens to be beside it. Feed it the literal v1 vector and ask what record it finds.

The test to add

Create TestDecodeReadsV1Bytes in record_test.go. Its input is the literal 24-byte vector from the codec reference:

5d6ebe2201020304050607080000000200000002676f4442

Do not call Encode in this test. The assertions should compare the decoded record against:

Timestamp: int64(0x0102030405060708)
Key:       []byte("go")
Value:     []byte("DB")

Compare keys and values with bytes.Equal. Compare the timestamp directly. If Decode returns an error, fail the test with the error.

Read order is safety order

When you implement Decode later, this order will matter:

  1. Check that at least 20 bytes exist before slicing the header.
  2. Read the stored checksum, timestamp, key length, and value length.
  3. Calculate the total length from the declared lengths and check that it is present before slicing key and value.
  4. Verify the CRC over the protected suffix.
  5. Return a record whose key and value are exactly the bytes described by the header.

Do not implement this yet. The new test should first reach the current TODO panic. That tells us the test has actually called the decoder.

Your task

  1. Add the decode test using a literal byte slice.
  2. Run go test ./internal/record.
  3. Send the result. It should show the encoder test passing and the decoder test stopping at Decode's TODO.

Later tests will cover short input and bad checksums. Keep this one narrow: correct bytes decode to the correct record.
